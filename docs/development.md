# RustPalm 开发与验证

当前首版面向 Mate 80 / HarmonyOS 7.0，采用 ArkTS 页面、C++ Node-API 桥和 RustDesk Rust 核心。应用标识暂定为 `com.rustpalm.client`，版本 0.1.6。最低兼容、编译及目标 SDK 均为 26.0.0，ABI 为 arm64-v8a 和 x86_64，分别用于手机和本地模拟器。

0.1.1 历史验证：2026-11-06 已通过双架构完整构建，未签名 HAP 为 47,308,332 字节。7 项逻辑回归与 3 组原生包校验回归通过，ARM64 与 x86_64 每组均核验了 14 个库，并已在 x86_64 Mate 80 模拟器安装、启动及初始化原生核心。后续版本的真机验证见下文。

本文中的 `dist/` 报告、`.local/` 日志及调试截图为本地验证记录，不包含在公开源码中。构建产物请自行生成，正式下载将通过 GitHub Releases 提供。

## 工程入口

| 路径 | 内容 |
| --- | --- |
| `app` | 可直接用 DevEco Studio 打开的 HarmonyOS 工程 |
| `app/entry/src/main/ets/pages` | 连接设置页及远控会话页 |
| `app/entry/src/main/cpp` | Node-API、NativeWindow、回调与 Surface 生命周期 |
| `third_party/rustdesk` | 固定上游源码及本地核心补丁，准备脚本可重新取得 |
| `patches/rustdesk-ohos.patch` | 核心会话隔离、安全连接和构建适配补丁 |
| `scripts` | 源码准备、构建与包核验工具 |
| `tests` | 坐标换算和协议消息分类的回归测试 |
| `dist` | 通过核验的 HAP 和 SHA-256，构建成功后生成 |

首版界面提供 RustDesk ID、服务器地址、公钥、可选中继和强制中继开关。电脑端应配置同一套服务器与公钥。连接后支持密码或电脑端人工允许、2FA 提示、只读模式、远程光标、单指点击、长按右键、拖动模式、双指滚动/缩放、缩放后双指平移、适应屏幕、画面刷新、文本提交及常用组合键。文本在手机输入框确认后整段发送，便于中文输入法完成组合输入。

0.1.4 起切后台、来电或锁屏不再主动关闭会话，而是暂停显示和输入，返回后恢复；退出会话或应用销毁时关闭连接。普通认证密码和验证码只用于当前会话，Rust 核心仍不记住凭据；用户主动保存的常用连接密码独立存于系统资产库。视频默认偏好 VP9。音频、剪贴板、文件传输、手机屏幕共享和语音的界面入口在首版范围之外。

## 构建

工具链安装说明见 [Windows 环境](windows-setup.md)。当前构建版本为 Rust 1.99.1、DevEco Studio 26.0.0.865、SDK 26.0.0.105、vcpkg 提交 `9eec002df1cd109f8f104cd966a763daf9751489`。

在工作区 PowerShell 执行完整构建。首次需要联网获取固定源码及依赖。

```powershell
$devecoRoot = 'D:\DevEcoStudio' # 示例，请改为自己的安装目录
pwsh -File .\scripts\build.ps1 -DevEcoRoot $devecoRoot
```

如需代理，在当前终端配置自己的 `HTTPS_PROXY`，并仅传入本次构建进程。不要把带凭据的代理地址写进仓库。

```powershell
pwsh -File .\scripts\build.ps1 -DevEcoRoot $devecoRoot -Proxy $env:HTTPS_PROXY
```

使用 `-DevEcoRoot` 指定 DevEco 安装位置。脚本使用 VS x64 宿主环境，随后明确指定独立 vcpkg 与鸿蒙目标工具链。

成功完成一次完整构建后，纯 UI 改动可使用以下命令。脚本会校验补丁、当前 Rust 差异与已编译核心的哈希。

```powershell
pwsh -File .\scripts\build.ps1 -DevEcoRoot $devecoRoot -SkipNative
```

合格输出为 `dist/RustPalm-0.1.6-universal-unsigned.hap`。正式交付路径仅在包内核验通过后更新，校验会检查 `libentry.so`、`librustdesk.so`、`libc++_shared.so`、各架构 ELF、必需 C ABI 导出、动态库依赖、包名、页面和权限。

独立运行本机逻辑测试及包检查。

```powershell
& "$devecoRoot\tools\node\node.exe" --test tests/remote-geometry.test.mjs tests/session-messages.test.mjs tests/remote-mouse.test.mjs tests/remote-gesture.test.mjs tests/remote-keys.test.mjs tests/favorite-model.test.mjs
python scripts/verify_hap.py dist/RustPalm-0.1.6-universal-unsigned.hap --ndk "$devecoRoot\sdk\default\openharmony\native"
```

## 签名和自行安装

公开工程默认使用空签名配置，产物为未签名调试 HAP。真机需要为同一包名配置有效的调试证书与 Profile，其中包含目标手机的 UDID。请在独立的私有工作副本中用 DevEco Studio 打开 `app`，在 Project Structure 的 Signing Configs 中登录自己的华为开发者账号并配置自动签名，连接手机后重新构建 signed HAP；不要把私有签名配置恢复到待公开的目录中。也可按华为文档使用已有证书和包含该设备的调试 Profile 手动签名。[华为签名说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-hmos-signing/)

Native 核心已由构建脚本分别放入 `app/entry/libs/arm64-v8a` 和 `app/entry/libs/x86_64`。在 DevEco 重新打包签名时，保留该目录。签名材料和口令保存在本机私有位置。

手机启用开发者选项及 USB 调试并认可本机后，可以用 SDK 的 hdc 检查设备，再安装生成的 signed HAP。下例的文件名需替换为实际签名输出。

```powershell
$hdc = "$devecoRoot\sdk\default\openharmony\toolchains\hdc.exe"
& $hdc list targets
& $hdc install -r '完整路径\entry-default-signed.hap'
```

若需要读取手机系统 API 或 UDID，按 DevEco 的签名流程操作。将完整系统版本和安装错误提供给开发者即可定位 SDK 或签名不匹配。[hdc 工具说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/hdc/)

## 真机验收

### 0.1.6 横屏显示空间

旧版本直接沿用竖屏布局，横屏打开文字输入时仍叠加标题、操作说明、完整工具栏、隐私
说明、输入框、快捷键及质量信息。按旧代码固定尺寸估算约占311vp，而当前手机横屏
窗口只有约366vp高；系统键盘再通过 RESIZE 缩小页面，固定控件仍保持原高，把视频
剩余空间挤到接近零。

现在根据主窗口方向选择布局，不使用已被键盘压缩的视频区域判断横屏，防止反复切换。
横屏不再显示独立顶部标题和多行说明：

- 普通模式仅底部44vp工具栏，包含键盘、右键、滚动、拖动、平移、只读、适应、刷新、连接路径及断开。
- 展开文字输入后，用44vp单行替换普通工具栏，包含收起、输入、显示/隐藏、发送、常用Ctrl/Esc/Enter和“更多”。窄窗口把快捷键收进更多。
- 完整修饰键、字母快捷键、鼠标模式、状态和锁屏断开放入可滚动浮层，不占常驻高度。浮层适应系统键盘上方的剩余高度，采用固定深色背景。
- 保留同一个XComponent和同一处TextInput声明；保持KeyboardAvoidMode.RESIZE，并由视频容器尺寸更新坐标换算。按用户补充要求，输入时仍允许桌面等比缩小，不增加强制放大或裁切。
- “收起”调用stopEditing关闭系统键盘并清空草稿。返回键优先关闭浮层/输入区；后台、结束会话和方向变化均关闭浮层。

API26手机横屏2832×1280px实测（像素，不是vp）：

| 状态 | App可用高度 | 桌面显示区高度 | 常驻功能区高度 |
| --- | ---: | ---: | ---: |
| 普通工具栏 | 1280 | 1126 | 154 |
| 文字栏展开、系统键盘未显示 | 1280 | 1126 | 154 |
| 系统键盘显示 | 503 | 349 | 154 |
| 点击收起后 | 1280 | 1126 | 154 |

系统键盘显示期间，“更多”可在其上方打开，保留焦点和测试草稿；关闭浮层并收起输入后
桌面恢复原高度且会话未中断。测试文字未发送到被控电脑。39项逻辑测试通过，新增
809×321及809×120vp横屏视口的四角/中心/黑边和键盘收缩坐标回归。双架构签名包
检查通过。不同输入法高度、分屏和旋转中输入仍需进一步设备回归。

构建日志 `.local/landscape-ui-build.log`；脱敏结果 `dist/device-test-report-0.1.6.json`。

### 0.1.5 Esc 组合键、主动断开锁屏及圆角

按用户新要求，取消 0.1.4 对 Esc 强制清除修饰键的限制：未选修饰键发送普通 Esc，
先点 Ctrl 再点 Esc 发送 Ctrl+Esc，也支持 Ctrl+Shift+Esc。修饰键发送一次后仍复位，
不会影响后续普通按键。实测 Ctrl+Esc 打开 Windows 开始菜单，随后直接点 Esc 关闭。

用户点击“断开”或主动返回时，若当前已认证、前台且允许键鼠控制，先释放拖动状态并
清除修饰键，再通过现有 `ffiInputKey` 发送 `LOCK_SCREEN`：down=true、press=false、
所有修饰键=false。这与 RustDesk 原生 LockScreen 的 Legacy 协议一致。消息与 Close
通过同一 FIFO，额外留出 500ms 异步处理时间；期间禁止输入和重复断开。后台、来电、
认证取消和网络异常触发的 `finish()` 不请求锁屏，也不修改持久化的断线锁屏选项。

只读或对端不允许控制时不能请求锁屏；连接已经断开时无法补发。协议没有远程锁屏
确认消息，返回0只说明已提交给核心，不能作为弱网下锁屏成功的保证。本次真机在浏览器
桌面主动断开后重新连接，观察到 Windows 锁屏，验证正常网络下流程成功。

常用连接卡片左侧直角来自内部 Normal 按钮的白色背景覆盖外层圆角。内部按钮现在
显式设置12vp圆角，外层 Row 按同样半径裁剪，四角及按压背景均保持圆角。

36 项逻辑测试、双架构签名包检查及上述三项真机检查通过。复用原 Rust 动态库，
构建日志位于 `.local/lock-ui-build.log`，脱敏结果见 `dist/device-test-report-0.1.5.json`。

### 0.1.4 按键、后台与常用连接

**Esc。** 已核对固定 RustDesk `KEY_MAP`：`VK_ESCAPE` 对应 Escape，原问题是 Ctrl
在组合键后一直锁定，随后 Ctrl+Esc 打开 Windows 开始菜单。现在工具栏修饰键只作用
于下一次按键，Esc 始终不带修饰键；A/C/V/Z 使用明确的 VK 名称。按钮高亮直接绑定
当前状态，避免 Builder 值参数使选中态滞后。

**后台。** `onBackground` 不再关闭会话。释放鼠标、清空 Ctrl/Alt/Shift 和敏感草稿，
暂停连接计时器、解绑视频，保留会话与网络线程。前台重新绑定 Surface 并刷新，实际
退出或销毁时关闭。申请一次 `requestSuspendDelay`，到期或前台恢复时主动取消，
不循环续期、不伪装音频或下载任务。系统本次授予 180000ms；实测约 51 秒后台返回
同一会话，恢复视频且未重新认证。来电涉及相同生命周期，但真实来电、长通话、低电量
及配额耗尽尚未专项测试。

该能力不是无限保活。短时任务单次通常最多 3 分钟，低电量通常 1 分钟，每日配额
和实际批准时长可动态调整；系统冻结、回收进程或网络断开仍可能结束连接。
参考[华为短时任务说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/transient-task/)。

**常用连接。** 首页支持名称、ID、可选 RustDesk 访问密码及新增/编辑/删除。记录整体
保存在系统 AssetStore：SECRET 为密码，普通属性只含 ID、名称、服务器地址/公钥及
是否存密码；列表只查询 ATTRIBUTES。资产仅解锁时可读，禁止同步，未申请卸载后保留。
编辑时不会加载旧密码，留空保留，输入新值替换或显式删除；改 ID 必须替换/删除旧密码。
连接前核对当前服务器地址与公钥，避免向另一套服务器使用旧凭据。无明文密码写入
preferences、路由参数或日志，不额外声明权限。

实测用户保存后可直接认证；强制关闭/重启 App 后仍保留常用记录，编辑框不回显密码，
留空保存后仍可直接认证。密码替换/删除及卸载后的行为留作专项回归。

**隐私输入。** 远控文字框默认 Password 类型、隐藏密码眼睛图标、禁用自动填充；
用户可主动切到“显示文字”用于普通文字和中文输入。发送、收起键盘、进入后台或结束
会话时清空草稿，重新打开默认隐藏。无法可靠识别远程应用的密码框，因此默认对所有
输入进行遮蔽。实测合成测试字符串显示掩码，UI 自动化树未显示原文，系统屏幕捕获
也屏蔽了含密码控件的窗口。

34 项逻辑回归和签名 HAP 双架构检查通过。实测 Ctrl 后 Esc 关闭远程菜单且未打开
开始菜单；系统资产保存/重启读取、后台恢复和隐私输入验证通过。复用既有 Rust 动态库，
未重编核心。记录见 `dist/device-test-report-0.1.4.json`。

### 0.1.3 触摸输入修复

RustDesk 服务端只在 MOVE（mask=0）事件中读取绝对坐标，DOWN/UP 仅操作当前光标
位置。旧页面将坐标附在按钮事件上，却未先移动光标，因此点击输入框、长按右键、
拖动起点均可能落在旧位置。现在 `RemoteMouse.ts` 统一生成 MOVE → DOWN/UP 序列。
滚轮前同样先移动到手势起点对应的远程栏目，随后发送 WHEEL（mask=3），其 x/y
表示滚动量。旧值 35 的低三位也会被识别为滚轮，实际问题是缺少定位和手势分支。

交互方式如下：

- 默认轻点左键，长按约 550ms 右键；也可点工具栏“右键”，再点击目标位置执行一次右键，随后恢复默认模式。
- 点“滚动”后，在目标栏目内单指上下滑动；默认双指平行上下滑动也可滚动，放大后仍可用。起点在黑边内时不发送滚轮。
- 双指捏合缩放；“平移”模式移动放大的画面，与远程滚轮明确区分。捏合判定同时要求比例变化和至少 12vp 间距变化，减少误触。
- “拖动”模式按住并移动目标。再点当前模式按钮可恢复普通点击；工具栏可横向滚动。
- 多指抬起按触点 ID 归一化，整个多指手势不再产生尾随左键点击。页面尺寸变化、失去控制权限、退出时释放按键。

手机文本输入框固定浅底、深色正文、清晰占位文字和绿色光标；认证输入框也采用显式
配色。键盘弹出后使用新的显示区域尺寸重算触摸坐标。

25 项逻辑回归通过，覆盖鼠标服务端行为模拟、手势累计、触点抬起、屏幕四角、
缩放平移、键盘收缩及认证消息。双架构签名 HAP 检查通过，0.1.3 已覆盖安装至手机。
真机已验证：点击远程网页搜索框获得焦点；手机浅底输入框清晰显示
`RustPalm-Test-123`，点发送后文字出现在远程输入框（未提交搜索）；单指滚动模式
分别向下、向上滚动网页；单次右键和默认长按均弹出远程上下文菜单。
物理双指缩放/滚动、旋转和长时间使用仍留作专项回归。
详细结果见 `dist/device-test-report-0.1.3.json`。

### 2026-11-06 真机认证排查

使用 API 26 的 ARM64 手机，通过 USB 调试和测试设备自己的调试签名覆盖安装。
实测自建服务器寻址及加密直连成功，连接进入密码认证阶段。

进一步实测定位到连接中断根因：正确密码提交后，核心依次发送 `peer_info` 和
`msgbox(type=success)`，后者表示“已连接，等待图像”。旧消息分类器把未识别的
`success` 当成错误，页面随即调用 `finish()` 主动断开。现已增加独立的 `connected`
分支，保留连接与视频绑定，并加入成功登录消息的回归测试。

另修复了两个认证反馈问题：核心的错误原因位于 `msgbox.title`，旧页面仅显示
`text`，使密码错误只显示英文重试提示；原来的 90 秒连接计时包含用户输入密码的时间。
现在密码错误显示中文原因，其他错误保留标题和正文；等待密码、验证码或电脑端人工
允许时暂停连接计时，提交认证后重新计时，并明确显示正在验证及认证响应超时。

新增 `RustPalmSession` 日志仅记录加密/直连布尔值、认证动作、是否重试和提交返回码，
不记录密码、公钥、服务器地址、设备 ID 或原始事件正文。可用 SDK 的
`hdc shell hilog -x -T RustPalmSession` 检查是否依次出现 `transport ready`、
`authentication submitted`、`authentication accepted`；返回码 0 仅表示提交到核心，
不代表电脑已接受。原生桥在首个 RGBA buffer 成功提交到 NativeWindow 后通知
`first_frame`，页面更新为“已连接”，同时记录 `first video frame presented`。
首页现提供强制中继开关，并传入新建会话的 `forceRelay` 参数。

已观察到正确密码认证成功、VP9 1920×1080 的 Windows 登录画面。随后用户按 Enter
登录 Windows 时出现 `Connection reset by peer (os error 104)`；尚未定位此项的原因。
测试中确认开发机与实际被控目标并非同一端点，因此没有用开发机的 RustDesk 日志
